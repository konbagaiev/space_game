## Goal

The base menu gets its "can this ship launch?" answer from several copies of the same check, and they have
drifted apart:

- **Bug A1.** On the **Map** view, "Autopilot to destination" ignores the gate. Unequip the hull in Loadout
  (the server allows it and then reports `launchable: false`). "Take off" next to the Autopilot button goes
  grey with the "can't launch" note, but Autopilot still flies a 0-HP ship out into the system.
- **Bug A4.** The predicate `!active || active.launchable !== false` is written twice: `canTakeOff` in
  `mainwindow.js` and `updateTakeoffGate` in `shop.js`. `#mw-mission-nav.disabled` has two writers. The red
  "can't launch" hint goes into **two** elements (`#mw-go-note` + `#mw-takeoff-note`). With a side mission
  active, both elements are visible on Missions, so the player reads the same red line twice.

After this change:
- One exported `canLaunch()` in `shop.js` is the only place the predicate exists.
- Every launcher checks it **in its own click handler**, not only through its button's `disabled`.
- The Map's Autopilot button renders disabled when the ship can't launch.
- The hint lives in exactly one element, `#mw-takeoff-note`.

What the player sees: with a required slot empty, nothing in the base menu can take the ship out, and the
reason is shown once.

## Decisions (settled — do not re-ask)

1. **`canLaunch()` lives in `client/src/shop.js`.** Verified: `shop.js` imports nothing from `mainwindow.js`
   or `welcome.js` (`shop.js:6-17`), and `mainwindow.js` already imports from `shop.js` (`mainwindow.js:26`).
   `welcome.js` imports `canLaunch` **from `shop.js`**, not from `mainwindow.js`, so no new cycle is added.
   `canTakeOff` is **deleted**, not kept as an alias.
2. **The in-flight overlay map (`openSystemMap`, `systemmap-ui.js:~326`) stays ungated.** It only opens in
   roam, where the ship has already launched. The mission-arrival "Start mission?" `onYes → launchMission`
   (`mainwindow.js:586`) also stays ungated, for the same reason: it fires only in roam.
3. **The `#mw-go` click handler gets the gate.** This gap is not in the source plan.
   `mainwindow.js:493-497` launches with no check today and relies only on `disabled`.
4. **`#mw-go-note` is deleted outright**: the HTML element, its CSS rule, the write in `shop.js`, and the
   display toggle in `updateGoButton`. `#mw-takeoff-note` sits under the launch bar `#mw-launch`, which is a
   direct child of `#mainwin` and is shown on every stage except Map (`#mainwin.map-open #mw-launch
   { display:none }`, `client/styles.css:440`). Map shows the same hint through its own action `note`
   (`.sysnav-hint`). The new scenario asserts that `#mw-takeoff-note` really is visible on Missions.
5. **`updateTakeoffGate` is the single writer** of `#mw-go.disabled`, `#mw-takeoff.disabled`,
   `#mw-mission-nav.disabled` and the note text. `updateGoButton` stops writing `nav.disabled`. Every path
   that changes `G.activeShip` already calls `updateTakeoffGate` (`renderBay` `shop.js:468`, `shop.js:586`,
   `mainwindow.js:175` on every view switch, `mainwindow.js:489`), so the disabled state can't go stale.
6. **The Map gets a new `mountSystemNav` option, `autopilotDisabled` (boolean, default `false`).** The base
   menu passes `!canLaunch()`. The overlay map passes nothing (Decision 2).
7. **No DECISIONS entry.** This removes duplication and makes no new trade-off (§30). §100's "one gate"
   statement simply becomes true.
8. **The guard is a new visual scenario, `54-launch-gate.mjs`**, kept out of 53 so 53 stays about the
   menu-idle invariant. It restores the shared worker player in a `finally` block.

### 1. One predicate: `canLaunch()` in `client/src/shop.js`

At `shop.js:439-455`, replace the comment and `updateTakeoffGate` with:

```js
// THE launch gate (DECISIONS §100): a required slot (hull/armor, engine, thruster) left empty → the server
// reports `launchable: false` and NOTHING in the base menu may take the ship out. This is the only copy of
// the predicate; every launcher checks it in its own handler (mainwindow.js takeOff / #mw-go /
// #mw-mission-nav / the Map's onAutopilot, welcome.js takeOff), and updateTakeoffGate mirrors it onto the
// buttons. The in-flight overlay map is ungated on purpose: in roam the ship has already launched.
export function canLaunch(active = G.activeShip) {
  return !active || active.launchable !== false;
}

// Reflect the gate on the global launch controls: the side-mission launch (#mw-go), Take off (#mw-takeoff)
// and the briefing's "Autopilot to destination" (#mw-mission-nav). The reason goes in ONE place,
// #mw-takeoff-note under the launch bar (the Map view shows it via its own action note instead).
export function updateTakeoffGate(active) {
  const ok = canLaunch(active);
  for (const id of ['mw-go', 'mw-takeoff', 'mw-mission-nav']) {
    const btn = document.getElementById(id);
    if (btn) btn.disabled = !ok;
  }
  const note = document.getElementById('mw-takeoff-note');
  if (note) note.textContent = ok ? '' : t('ui.shop.cant_launch');
}
```

(`G` is already imported at `shop.js:7`, `t` at `:13`.) Update the header comment at `shop.js:5`, which
lists `updateTakeoffGate` among the exports, so it also mentions `canLaunch`.
