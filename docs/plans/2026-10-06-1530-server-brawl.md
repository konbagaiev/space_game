# Server-run bot brawl (`?netbrawl`) + in-process server load metrics

> **Status: PLAN (2026-10-06), feature `2026-10-06-1530-server-brawl`.** This plan implements the brief

> while checking the brief against the code. Where this file and the brief disagree, **this file wins**. The

## Goal

The bot brawl (N v N Sentinel bots over the home station, `?brawl`) is our repeatable load test. Today it
only measures the TAB, because the tab simulates the fight. This change adds a second URL, **`?netbrawl=N`**.
The same fight runs inside a **server netsim room**, the tab only renders the snapshots it receives, and the
server **measures what that costs**: step time per tick, snapshot cost and bytes, event-loop delay, CPU,
memory, and how many rooms it holds. The numbers travel in the snapshot once per second as an `srv` block.
The result card shows them, and the tab copies them into its existing `/api/perf` sample, so the analysis
stays one SQL table. The server also prints a JSON log line every 10 s per room. A headless tool,
`server/tools/brawl-capacity.mjs`, answers the roadmap question "rooms per core at N = 20/50/100".
`?brawl` (the in-tab brawl) **does not change in behaviour**.

## Decisions (all settled — do not re-ask)

**From the brief (maintainer, 2026-10-06):**

1. **Its own URL: `?netbrawl=N`.** A bare `?netbrawl` shows the same setup panel as `?brawl`, and its
   Start reloads into `?netbrawl=<n>&tier=<t>`. `?netbrawl` implies the netsim connection by itself; the
   tester never adds `netsim=1`. If `?brawl` and `?netbrawl` are both present, **`?netbrawl` wins**. The flag
   is never sticky. The setup panel and the card both say which mode ran: "Simulated by: this tab" or
   "Simulated by: server room". The result sample carries `server: true|false`.
2. **The room runs `brawlTick` instead of `simTick` when `world.brawl` exists**, the same routing as
   `client/src/sim.js:523`. The room **arms** the brawl on the first client input.
3. **The player is the spectator**, exactly as in the local brawl: alive, parked `BRAWL_SPECTATOR_PARK` east,
   never stepped. The camera and view-target logic in `brawl-host.js` works from the ghost world
   (`netsim-world.js`).
4. **The snapshot gains a `brawl` block.** It is extended here; see Decision 13.
5. **No economy, ever.** A brawl room never fires `onEconomy`, sends no `/api/games`, records no session,
   and is never banked.
6. **Abuse guard:** at most **2 concurrent brawl rooms per process**, and `n` is clamped to `1..BRAWL_N_MAX`
   (100). A third brawl join is refused with a protocol `error`, which the client shows on the setup panel.
7. **Server metrics** are measured inside the process, per room, once per second. They travel in the
   snapshot as `srv` (once per second, not on every snapshot), appear on the card, are copied into the tab's
   `/api/perf` sample, and are logged as one JSON line per room every 10 s.
8. **Headless capacity tool:** `server/tools/brawl-capacity.mjs`.
9. **Determinism is checked on the same engine only.** A Node room's brawl fingerprint must equal
   `sim-core/brawl.js` run headless in Node, for the same N and `BRAWL_SEED`. Never compare it with a
   browser run (§151).

**From discovery (maintainer answers):**

10. **Room lifetime.**
    - (a) When the result card is shown, the client sends `bye` and closes the link.
    - (b) Server backstop: a brawl room closes itself **`BRAWL_ROOM_MAX_MS = (BRAWL_SEC_MAX + 30) × 1000` =
      330 s after it was created**, whether it is armed or not. It sends a final snapshot with `ended: true`,
      then closes with code `4001` and reason `brawl-expired`.
    - (c) On the server, `ended` = `brawlOver(world)` (one side wiped out) **or** the backstop firing.
11. **The link is lost.** `?netbrawl` **never falls back to the local simulation**. If the cap refuses the
    join (or any failure arrives before the run is armed), the client shows the error on the setup panel.
    If the link drops during the run, the run ends immediately. The card shows partial results with
    `endedBy: 'link-lost'` and the close code, and the result sample carries the same two fields. The close codes are 4001 (backstop) and 4002 (cap); the slow-link guard (S6) **terminates** the socket, so
    the client sees an abnormal close (1006). All of them go through this one path. Keep this
    path to a single function: a later, separate pipeline run will replace it with a general reconnect for
    all rooms (see "Next").

**Corrections and additions found in discovery (part of this plan, do not revert):**

12. **The ace look must cross the wire.** Red bots are `makeAce` hulls whose `name` is `'Sentinel duelist'`
    (`client/src/sim-core/ace.js:36,67`), which is **not a catalog ship name**. The client's
    `spawnGhost` (`client/src/netsim-world.js:121-126`) looks the name up in `catalog.shipByName` and
    **returns null**, so today every red brawl bot would be invisible over netsim. The enemy `describe`
    (`server/src/netsim/room.js:110-115`) also sends no `accent`. Fix:
    - `describe` adds `ace: 1` when `e.pilot === ACE_PILOT`;
    - `spawnGhost` builds such a ghost with `makeAce(world.catalog, 0)`, the same constructor the sim uses,
      the way allies already use `makeAlly`. That gives the right hull, colour and `accent`.
13. **The `brawl` block** is `{ n, armed, ended, ticks, alive: [blue, red], killsByBlue, killsByRed, fp }`.
    `fp` is the full `world.brawl.fingerprint` array (at most 30 entries of 3 numbers). It is needed because
    snapshots go out only on even room ticks (`room.js:236`), while `b.ticks` counts from arming at an
    arbitrary room tick. Half the time no snapshot lands on a 10-sim-second boundary, so the client could not
    rebuild the fingerprint itself. **The server's `b.ticks` is the one source of truth for sim seconds.**
14. **The client keeps a mirror `world.brawl`.** It is filled from the snapshot block and is **never
    stepped**: it carries `server: true`, and `brawlTick` returns early on it.
15. **Pick and follow use the network id** (`netState.idOf`) under netbrawl. Ghosts have no `_aimOrdinal`.
16. **Health is sampled once per second for the whole process, and the readings are cached.**
    `health.sample()` resets the one shared histogram (`server/src/netsim/health.js:46`; see the warning at
    `:58`), and the driver's stall warning already calls `health().line()`. Two rooms each sampling would
    zero each other's window. CPU, RSS, heap, event loop and load are **process** metrics and are labelled
    as such (`srv.proc`).
17. **More `srv` fields:**
    - `snapMs`: the time for `takeSnapshot` + `JSON.stringify` + `ws.send`. Stringify **once** and reuse
      the string's length for the byte count.
    - `behind`: the per-second delta of `driver.behind`.
    - `bufMax`: the largest `ws.bufferedAmount` seen that second.

    Measured headless: at N = 100 a snapshot peaks at ~62 KB without spawn descriptors (~1.9 MB/s at 30 Hz).
    `send()` has no backpressure, so this must be visible. (A brawl room also closes a hopeless link; see `BRAWL_MAX_BUFFERED` in S6.)
18. **The arming handshake under netbrawl.** The room spawns the bots on `start`, and their descriptors
    reach the tab. When the first ghost batch is attached, the tab requests a **scene re-warm**
    (`G.needsSceneWarm = true`); this compiles the ally and ace hulls behind the veil. The tab arms its own
    wall clock when that warm is done, and **only then starts sending input**. The room arms on that first
    input. So the 60 s wall clock and the server's sim ticks both start when the tab is actually watching,
    and the card's first window is not polluted by late shader compiles. The brawl level's single inert
    phase warms no enemy types (`withBrawlRoom`, `sim-core/brawl.js:63`). Locally the bots are warmed only
    because they are spawned in the same frame as `reset()`.
19. **A brawl room re-spawns its brawl in `restart()`.** The client's `start` message calls
    `room.restart()`, which calls `clearAndPlaceRun`. That **empties `world.allies` / `world.enemies`**
    (`client/src/sim-core/reset-world.js:36-40`) but leaves `world.brawl` in place, so without a re-spawn
    the fight would be "over" before it began. In a brawl room `restart()` therefore:
    - discards the stale spawn descriptors,
    - re-seeds `BRAWL_SEED`,
    - calls `spawnBrawl` again, ignoring `pose`.

    `createSimWorld({ brawl })` still spawns as well, so the capacity tool and the headless tests get a ready
    world without a `start`.
20. **Brawl wins over the other dev rooms.** `createSimWorld({ brawl })` ignores `ally`, `lancer` and
    `duel`, and forces the level to `BRAWL_LEVEL` (`'level-1'`). `BRAWL_LEVEL` moves into
    `sim-core/brawl.js`, and `brawl-dev.js` re-exports it.
21. **Brawl rooms skip `loadShip`.** No DB read: the spectator ship never moves, so the catalog default is
    fine.
22. **Both `srv` and the 10 s log line cover every room, not only brawl rooms.** It is one code path in the
    driver and costs almost nothing. The client reads `srv` only when it is present; campaign netsim simply
    ignores it unless `?dev` perf is on, in which case it is also copied into the perf sample.

**Known limitation (documented, not fixed):** the seeded stream in `sim-core/sim-random.js` is
**process-global**. `pilotRandom` re-keys whenever the installed seed changes (`step-ally.js:77-80`). Two
brawl rooms share `BRAWL_SEED`, so they do not disturb each other. But a **campaign** netsim room created
while a brawl runs calls `seedSim(<its seed>)`, which re-keys the brawl pilots, so that brawl is no longer
fingerprint-identical to the headless run. This pre-dates this change (every room already seeds the one
stream). The reverse also holds: creating or restarting a brawl room calls `seedSim(BRAWL_SEED)` and so
re-seeds a running **campaign** room's shared stream too. That is already true between two campaign rooms
today and is harmless (live rooms carry no determinism contract); it only matters for an offline
fingerprint comparison. The determinism test below is single-room by design. Say both in SUMMARY.

- In the pump loop (`:46-51`):
  ```js

    const s1 = hrNow(); const snap = room.takeSnapshot();

  ```

**S6. `server/src/netsim/socket.js`**
- Add constants next to `MAX_ROOMS` (`:33`):
  - `export const MAX_BRAWL_ROOMS = 2;`
  - `export const BRAWL_ROOM_MAX_MS = (BRAWL_SEC_MAX + 30) * 1000;`
  - `export const BRAWL_MAX_BUFFERED = 8 * 1024 * 1024;` This is the **slow-link guard** (critic,
    blocking). Prod runs with `mem_limit 1g`. A 100 v 100 room peaks at ~1.9 MB/s per client and `send()`
    has no backpressure. The ticket is anonymous, and inbound input keeps resetting the idle close. So one
    slow or malicious client could grow the server's send buffer until the process is OOM-killed, taking
    every room with it. The guard caps that at 8 MB per brawl room, about 4 s of peak output.

  `BRAWL_SEC_MAX` is 300 in `client/src/brawl-dev.js:34`, but `brawl-dev.js` imports `graphics.js`, so
  either move `BRAWL_SEC_MAX` (with its MIN/DEFAULT siblings) into `sim-core/brawl.js` and re-export it from
  `brawl-dev.js` like `BRAWL_LEVEL`, or hard-code 330 000 with a comment. **Prefer the move.**
- `attachNetsim(httpServer, { …, brawlMaxMs = BRAWL_ROOM_MAX_MS })`. Keep a `let brawlRooms = 0` and a
  `let roomSeq = 0`. Call `health().startSampler()` once inside `attachNetsim`.
- `send(ws, obj)` (`:189`) returns `s.length` (the string it stringified once), or 0 when the socket is not
  open. The driver's `onSnapshot` returns `send(ws, snap)`.
- In `open()`, **synchronously, before the first `await`** (to avoid a race where two joins both pass the
  check while awaiting):
  ```js
  const brawlRaw = Number.parseInt(params.get('brawl'), 10);
  const brawl = Number.isFinite(brawlRaw) && brawlRaw > 0 ? clampBrawlN(brawlRaw) : null;
  if (brawl) {
    if (brawlRooms >= MAX_BRAWL_ROOMS) {
      send(ws, { type: 'error', error: 'brawl-busy', max: MAX_BRAWL_ROOMS });
      return ws.close(4002, 'brawl rooms full');
    }
    brawlRooms++;
  }
  ```
  A `pending` buffer is not needed on this path. Release the slot exactly once through one helper,
  `const release = () => { if (counted) { counted = false; brawlRooms--; } }` with `let counted = !!brawl`.
  Call `release()` from all three exit paths:
  - `teardown`;
  - the `createRoom` failure path;
  - **the outer `(async () => { … })().catch(…)` of `open()`** (`socket.js:172-175`).

  A join that throws anywhere must not leak a slot, or two failures would lock `?netbrawl` out until the
  process restarts.
- For a brawl join, skip `loadShip` (Decision 21) and call
  `createRoom({ levelName, seed, ship, ally, lancer, beam, brawl, onEconomy: brawl ? null : makeEconomySink(…) })`.
  No sink at all, so no economy, belt and braces.
- Driver:
  `createDriver(room, { onSnapshot, label: id, log, bufferedAmount: () => ws.bufferedAmount, procStats: () => ({ rooms: sessions.size, brawlRooms, clients: sessions.size }) })`,
  where `id = ++roomSeq`. **Pass the socket's `log`** (the one `attachNetsim` received), so the 10 s line
  and the tests' log spy use it; `log.log?.(…)` falls back to nothing when the injected logger has no
  `log`. The default `console` provides `log`. `onSnapshot` holds the slow-link guard for brawl rooms:
  ```js
  const onSnapshot = (snap) => {
    if (brawl && ws.bufferedAmount > BRAWL_MAX_BUFFERED) {
      log.warn?.(`[netsim] slow link: brawl room ${id} player=${playerId} buffered=${ws.bufferedAmount} — closing`);
      driver.stop(); ws.terminate();   // NOT close(): a close handshake would queue behind 8 MB of unsent data
      return 0;
    }
    return send(ws, snap);
  };
  ```
  Declare `driver` with `let` before the closure, or reference it lazily, so the closure can stop it. The
  check runs before each send, at snapshot rate (30 Hz). **Maintainer amendment (review gate, 2026-10-06):
  `ws.terminate()`, not `ws.close(4003, 'slow-link')`.** A close handshake is queued behind the very 8 MB
  of unsent data that tripped the guard, so the slot would stay taken for up to ~30 s; `terminate()` destroys
  the TCP socket at once, the server-side `close` event fires immediately, `teardown` runs and releases the
  slot. The server log line still says `slow link`. Campaign rooms are unaffected; dropping snapshots instead
  of closing stays a non-goal. The client needs no change: any close under netbrawl is already
  `brawlLinkLost`, so the card shows `endedBy: 'link-lost'` with close code **1006** (abnormal close).
- Backstop:
  ```js
  const expire = brawl ? setTimeout(() => {
    room.endBrawl(); send(ws, room.takeSnapshot()); ws.close(4001, 'brawl-expired');
  }, brawlMaxMs) : null;
  expire?.unref?.();
  ```
  `clearTimeout(expire)` in `teardown`.
- The `join`/`leave` log lines gain `brawl=${brawl ?? '-'}`.
- `get brawlRooms()` on the returned handle, for the tests.
- Two test-only options on `attachNetsim`, both defaulting to the production behaviour:
  - `onSession = null`, called with the session object once it exists, so a test can stub `ws.bufferedAmount`;
  - `createRoomFn = createRoom`, so a test can make a join throw.

**S8. `server/tools/brawl-capacity.mjs`** (new). Usage:
`node server/tools/brawl-capacity.mjs [--n 20,50,100] [--k 1,2,4,8] [--sec 60]`.
- For each (N, K):
  - create K rooms with `createRoom({ levelName: 'level-1', brawl: N })`;
  - call `room.pushInput([{ t: 0, k: [] }])` on each, which arms it on its first step;
  - step all K rooms round-robin on this one thread for `sec × 60` ticks;
  - time every `stepOnce` and, when `dueForSnapshot()`, `JSON.stringify(room.takeSnapshot())` (its time and
    length), with `performance.now()`.
- Print one table row per (N, K):
  - step ms avg / p95 / max;
  - snap ms avg / max;
  - snapshot KB avg / max;
  - KB/s per client (avg bytes × 30 / 1024);
  - **process ms per wall second per room** = `60 × stepAvg + 30 × snapAvg`;
  - **rooms per core** = `floor(1000 / that)`, plus a p95-based figure;
  - the same numbers for the **first 10 sim-s only** (the fight thins out fast: at N = 100 it is ~16 v 3 by
    60 s, measured headless).
- Header comment:
